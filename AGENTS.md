# Working on ttukorvpallikool.ee

Guidance for any AI agent or new developer picking up this repo. Read it
before changing anything: this codebase has several traps that make a change
*look* applied when it is not, and one that will make you believe you deleted
the site's content when you have not.

---

## 1. What this is

Trilingual (Estonian / English / Russian) Jekyll site for TTÜ Korvpallikool, a
Tallinn basketball club of ~700 players across 10 training locations.

- **Deploys** to Netlify from **`master`**. Pushing to `master` publishes.
- **Estonian is the default language** and lives at `/`. The others are at
  `/en/` and `/ru/`, generated by jekyll-polyglot.
- The site's job is conversion: get a parent to enquire via the contact form.
  That form is the only conversion path. Treat it as critical.

**Stack:** Jekyll 4.3.3 · jekyll-polyglot · jekyll-minifier · Bootstrap 3.3.7
and jQuery from CDN · Decap (Netlify) CMS at `/admin/` via git-gateway.

Ruby is pinned to 3.2.2 in `.ruby-version`.

## 2. Running it

```bash
bundle install
bundle exec jekyll serve --livereload     # http://127.0.0.1:4000
```

### Do not run `jekyll build` while `jekyll serve` is running

This is the most expensive trap in the repo and it has already cost hours.
`serve` watches and rewrites `_site` continuously. A concurrent `build` writes
the same directory, and the two interleave into a **partially written site** —
whole sections vanish from the served page while the source is perfectly fine.

If content appears to have disappeared, **this is almost certainly why.** Do
not start "fixing" the source. Instead:

```bash
pkill -f "jekyll serve"
rm -rf _site && bundle exec jekyll build      # confirm the source is intact
bundle exec jekyll serve --livereload         # then restart the server
```

While `serve` is running, just save a file and let livereload rebuild.

### Other environment notes

- A fresh clone's first build may die with `Errno::EINVAL` on `.jekyll-cache`.
  That is Dropbox indexing the new files, not a repo fault. Wait, re-run.
- **`_site` is regenerated on every build.** Anything you drop in there for
  debugging is deleted by the next rebuild. Write probe pages at the repo
  root instead, and **not** with a leading underscore — Jekyll excludes
  `_*` paths, so `_probe.html` will silently 404.

## 3. Repository map

```
_config.yml            site config, languages, lang_codes, collections, ga_id
_data/{ee,en,ru}/content.yml    ALL user-facing copy
_data/galleries.yml    member-club logos and sponsor logos
_data/instagram.yml    Instagram feed id and section toggle
_includes/             page sections (navbar, footer, contact, ...)
_layouts/              default.html (homepage) + one per landing page
_services/             the three service blurbs, a collection, output:false
css/landing-page.css   the entire stylesheet, token block at the top
js/ttu.js              form submit, location picker, mobile nav
img/                   photography, logos, hero video
sitemap.xml            hand-rolled template, walks all languages
```

### Adding copy

Copy lives in `_data/{ee,en,ru}/content.yml`, never in templates. **A new
string means adding the same key to all three files.** A missing key renders
empty with no error, so check all three languages after any copy change.

### Adding a page

A page is a stub at the repo root carrying `layout` and `permalink` front
matter; the markup lives in `_layouts/`. Then **add it to `sitemap.xml`** —
that is a hand-written template, not a plugin, so new pages do not appear on
their own. See §6 for why the plugin was rejected.

## 4. The style system

Everything visual is driven by the token block at the top of
`css/landing-page.css`. **Never put a raw colour or font-size literal in a
rule.** Use the tokens; that block is the entire design system.

**Colour.** `--brand-400` … `--brand-900` plus named neutrals (`--ink`,
`--muted`, `--paper`, `--surface`, `--line`, `--line-strong`). The ramp is
tuned to the basketball-school logo: its magentas centre on hue 325.5 at
59–77% saturation. `--brand-500` `#E4067E` is deliberately *not* on that
curve — it is TalTech's university brand magenta, used as the accent and
hover colour. `--brand-600` is the primary action colour.

**Five icon files carry the brand colour as a literal**, because they are
rendered as `<img>` and CSS cannot reach inside them: `ic_email_black_24px`,
`ic_phone_black_24px`, `ic_home_black_24px`, `fb` and `insta` in `/img`. They
were `#800F43` — matching no token at all — until they were repointed at
`--brand-600`. **If you change `--brand-600`, update those five too**, or the
footer icons drift away from the text beside them.

**If you change a brand colour, hold lightness constant.** Every contrast
ratio depends on it; `--brand-600` must stay ≥4.5:1 on white (it is 7.2:1).

**Type.** One family — Mulish, the closest free stand-in for the brand's
Proxima Nova, and it carries Cyrillic for the Russian pages — on one fluid
`rem` scale. `--fw-display` 900 for h1/h2, `--fw-strong` 700 for h3 and
buttons.

**Buttons.** One shape for every CTA: `--btn-height` 48px, inline-flex
centred. Primary is solid brand; `.btn-ttu-inverse` is the same shape
outlined, and inverts to white inside brand-coloured sections.

**Container.** Content sits on `--container-max` 1200px. Only the nav bar
runs wide (`--container-wide` 1400px) so its CTA can sit at the far right.

**Focus** rings live on `:focus-visible` only — mouse clicks show nothing,
keyboard users get a brand ring. Do not reintroduce `:focus` outlines.

## 5. Traps that will waste your time

### 5.1 Bootstrap 3 sets `html { font-size: 10px }`

Every `rem` computes at 62.5% unless the root is reset. It is reset, in the
token block. **Do not remove that reset** or the whole type scale silently
shrinks by a third.

### 5.2 Bootstrap selectors routinely outrank yours

`#custom-nav a` is an ID selector. `.navbar-nav > li > a` beats a bare class.
`.spordiklass-content a` beats `.btn-ttu-inverse`.

Fix by **matching specificity**, not by adding `!important`. There are 14
`!important` declarations left and they are all this problem, unresolved.

### 5.3 Verify with computed styles, not screenshots

Several real bugs here were invisible in a screenshot but obvious in
`getComputedStyle`: a nav CTA rendering brand-on-brand, a button stuck at
54px, form fields glowing Bootstrap-blue, a secondary button inheriting
`font-weight:900` and an underline.

The reverse also applies: **measuring geometry is not the same as looking.**
The footer columns measured as perfect equal thirds while reading as a mess,
because the three columns used different type treatments. Do both.

### 5.4 Deleting CSS rules by regex can orphan a brace

A regex deletion once emptied a `@media` block but left its opening `{`.
Every rule written afterwards was nested inside that query and only applied
below 991px — the change looked completely ignored on desktop.

**After any scripted CSS edit, check the braces balance:**

```bash
python3 -c "s=open('css/landing-page.css').read(); print(s.count('{'), s.count('}'))"
```

### 5.5 Headless Chrome has a 500px minimum window

`--window-size=390` gives you a **390px crop of a 500px layout**, not a
390px viewport. That looks like catastrophic overflow that does not exist.
For a genuine narrow viewport, load the site in an iframe of the width you
want and screenshot the harness page.

### 5.6 The browser caches CSS and images hard

If a change is not visible, confirm what is actually being served before
touching the source:

```bash
curl -s http://127.0.0.1:4000/css/landing-page.css | grep -c 'the-thing-you-added'
```

Then hard-reload (⌘⇧R). Images are not cache-busted at all.

## 6. Decisions already made, with reasons

Do not undo these without reading why.

- **The three service blurbs are a `_services` collection with
  `output: false`.** They were `_posts` with `layout: default`, so each one
  rendered the entire homepage — 27 near-duplicate pages competing with the
  real one in search. They still render inline on the homepage; they generate
  no standalone pages. Site went from 39 pages to 12.

- **The sitemap is a hand-rolled template, not `jekyll-sitemap`.** Polyglot
  forks a process per language, so the plugin only ever sees one of them: it
  emitted 4 URLs, including `/admin/`. The template walks every language for
  every real page — 12 URLs with hreflang alternates.

- **hreflang is built from `site.lang_codes`, not polyglot's tag.** Polyglot
  emitted `hreflang="ee"`, which is not a valid ISO 639-1 code for Estonian
  (`et` is), so search engines ignored it entirely.

- **`site.url` is https.** Canonical must match what is actually served.

- **The Netlify Identity widget is not loaded site-wide.** `admin/index.html`
  loads its own copy, so the site-wide one was 235 KB of waste on every
  visitor page. *Caveat:* git-gateway invite and recovery links land on the
  site root and need the widget to catch them — this needs a real-world test
  with an actual CMS invite before it merges.

- **Sponsor logos carry a `premuted` flag** in `_data/galleries.yml`. Nike and
  Sportland were supplied already muted grey (`#D1D1D1`); the row's blanket
  `opacity: 0.2` would have rendered them nearly invisible. The mute now
  applies only to full-colour logos.

- **The Instagram feed is client-side on purpose.** It was first built to
  fetch at build time, which bought static HTML, self-hosted images and
  indexable captions — none of which are worth much for three social tiles —
  and cost a Ruby script, a cron workflow, a Netlify build hook, a GitHub
  secret, a 60-day silent-disable failure mode, and a feed that went stale
  between deploys. For a section called "what's new" on a site that deploys a
  few times a year, freshness wins. Do not reintroduce the build-time fetch
  without a reason better than SEO.

- **Form validation messages live in `data-msg`, not in an inline
  `oninvalid`.** They used to be interpolated straight into a JS string
  literal, so the apostrophe in "Please specify child's year of birth" was a
  syntax error and those fields silently fell back to the browser's default
  message. The copy is CMS-editable, so any editor could reintroduce that.
  `js/ttu.js` now reads `data-msg` (written through Liquid's `escape`) and
  calls `setCustomValidity` itself. Do not put copy back into inline JS.

- **Do not put `novalidate` on `#ttu-form`.** `ttu.js` does no validation of
  its own — the submit handler is commented "pretend we don't need
  validation" — so `novalidate` means an empty enquiry posts to Formspree.

- **Do not source brand logos yourself.** Nike in particular does not
  distribute its mark for third-party use; the correct file comes from the
  sponsor with the sponsorship. A scraped copy risks the wrong variant on a
  page whose whole purpose is showing genuine endorsement.

- **Compression is not automatically a win.** A blanket re-encode pass made
  three already-well-compressed images *larger*. Measure before and after and
  keep only the wins.

## 7. Current state and what is left

The `style-cleanup` branch is well ahead of `master` and **nothing on it has
deployed**. `master` is untouched.

### Needs a human, not an agent

- **GA4 / analytics.** `ga_id` in `_config.yml` currently holds the old
  `UA-108664795-1`, which **is still reporting** because Google auto-created a
  GA4 property behind it with a connected site tag. Do not "fix" this by
  removing it — that was done once and broke working analytics.
- **Instagram** is live. It is fetched **in the browser** from Behold's public
  JSON endpoint (`feeds.behold.so/{id}`), so it is always current and needs no
  rebuild when the club posts. Behold holds the Instagram token and refreshes
  it, so nothing expires. The feed id lives in `_data/instagram.yml` rather
  than an environment variable because it is public by design: it appears
  inside the image URLs the feed returns. The section carries `is-loading`
  and only unhides once tiles render, so a blocked or failed fetch leaves no
  empty heading. Rendering is in `js/ttu.js`, using `textContent` for captions
  and only following `https://` URLs the feed itself returned.
- **Test a CMS invite link** before merging (see the Identity caveat above).

### Open technical work

- Images have no WebP/AVIF, no `srcset`, and no intrinsic `width`/`height`
  (the last causes layout shift). The hero video is 4.6 MB across mp4+webm.
- 14 `!important` declarations, all fighting Bootstrap; retiring them needs
  markup changes.
- Bootstrap 3 has been EOL since 2019 and is still the layout engine. A big
  change for little visible gain — deliberately left alone.
- The contact form works but posts to Formspree's legacy `formspree.io/{email}`
  endpoint. Worth migrating to `formspree.io/f/{id}` before the old shape is
  retired: the AJAX handler treats any 2xx as success, so a failure would be
  silent. The enquirer's name is now included in the payload; from 2022 until
  this branch the field was required of the visitor but never sent.
- `_includes/sporditeraapia.html` exists but is included nowhere.

## 8. Working style that fits this repo

1. **Change one thing, then verify what is actually served** — `curl` the
   built output or read computed styles. Do not trust that an edit landed.
2. **Check braces after scripted CSS edits.**
3. **Look at the page as well as measuring it.** Geometry can be correct while
   the design is wrong.
4. **Copy changes touch three files.** Always all three languages.
5. **Say when a claim is unverified.** Several confident assertions here turned
   out to be wrong — the analytics were declared dead when they were live, and
   page weight was quoted uncompressed as if it were transfer size. If you have
   not measured it, say so.
