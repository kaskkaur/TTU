Modernisation audit & work plan

A read of the current site as built, what is actually broken today, and a staged plan to modernise it without changing the brand or inventing new requirements.

Scope ttukorvpallikool.ee (ee/en/ru) Branch redesign-2026 Stack Jekyll 4.3.3 · polyglot · Netlify Date 3 Sept 2026

01

The verdict, up front

Recommendation

Stay on Jekyll. Fix what is broken, systematise the styles, redesign the surface.

Nothing in this site's problems is Jekyll's fault. The stack is a reasonable fit for a five-page trilingual brochure site and a migration would spend weeks buying almost nothing. The urgent work is elsewhere: the site has had no analytics for roughly three years, ships 27 near-duplicate copies of its own homepage to search engines, and loads 676 KB of third-party code — including an unminified jQuery — to render static text.

One thing I could not settle from here. The contact form — the site's only conversion path — posts to Formspree's legacy formspree.io/{email} endpoint, a format Formspree has long since replaced with /f/{id}. A GET returns 405 for both the old and new shapes, so that tells us nothing, and I did not POST because it would send a real email. Send one test submission and confirm it arrives before anything else on this list.

04

The style system

This is the systematisation ask, and it is the clearest single win. The current CSS has no tokens — 1,443 lines, 30 !important, and one breakpoint.

Today — eight pinks

Eight near-identical brand colours, arrived at one hex at a time. Several differ by a couple of percent in lightness and are visually indistinguishable.

E4067E AA1352 9F1053 9B054F 710D3C 74093A 54092D 9F004E

Proposed — one ramp

Same brand, four steps with defined roles. TalTech magenta stays exactly as it is and becomes the single accent.

Accent — CTA, rules, hover#E4067E
Mid — large surfaces#8E0F4A
Deep — plates, footer#4C0A2A
Ground — hero base#33061C
The brand palette already passes accessibility, which is good news and means it does not need to change. Measured: magenta on white 4.54:1, button plum 7.18:1, deep plum 11.51:1 — all clear of WCAG AA. The single failure is #ACADAC grey on white at 2.25:1, used for muted text; replacing it with the proposed #6E5C64 fixes it and warms the neutral toward the accent at the same time.

Type

Font sizes are currently declared in px, pt, em and % — mixed within the same stylesheet, with pt (a print unit) on headings. There is one font-family declaration, for Quattrocento Sans, while three weights of Proxima Nova sit unused in /fonts.

The proposal is a single fluid scale in rem/clamp() and one family doing all the work. Proxima Nova is the brand face and the club already licenses it — it should be converted to woff2, subset to Latin + Cyrillic (the site is trilingual), and actually wired up with @font-face. The mockups use Chivo and Archivo as stand-ins because Proxima Nova cannot be served from a public CDN.

Breakpoints

All three media queries in the stylesheet are max-width: 767px. There is no tablet or intermediate behaviour, which is why the recent history is a run of commits named "mobile fixes", "mobile fixes, layout fixes" and "final mobie fix". A layout built on CSS Grid with auto-fill and fluid type needs far fewer explicit breakpoints — the mockups use two.

05

Should it stay on Jekyll?

Asked properly, since it is the one decision here that is expensive to reverse.

Stay on Jekyll Recommended

The content is three languages of one small brochure site. Polyglot handles the i18n, Netlify builds it, Decap CMS is already wired to /admin/, and the build is under a second. Every problem in this document is fixable in place.

Cost — zero. Risk — polyglot is lightly maintained, and its fork-based parallel build is the fragile part.

Migrate to Astro or 11ty

Better i18n ergonomics, image optimisation in the build, a toolchain more people can hire for. Genuinely nicer — but it buys tooling, not capability, and the content would have to be moved by hand.

Cost — 2–3 weeks. Worth revisiting only if a real new requirement appears.

Two Jekyll-specific caveats worth writing down. First, parallel_localization forks a process per language; that fork is where the build breaks under filesystem contention, and setting it to false costs almost nothing at this size. Second, .ruby-version pins 3.2.2 — fine today, but the Ruby dependency is the main long-term maintenance cost of staying, and it is the thing that will eventually force the question.

06

The work plan

Ordered so that the cheapest, highest-consequence work lands first and nothing later depends on the redesign being agreed.

Phase 0~half a day

Stop the bleeding

  • Send one test enquiry through the live form; migrate to formspree.io/f/{id} if it fails
  • Replace UA with GA4 or Plausible — nothing else can be measured until this exists
  • Add lang to <html> per language
  • Move the Netlify Identity widget to /admin/ only
  • Swap unminified jQuery for the minified build
  • Delete the 1-second page-loader delay

Roughly 500 KB per page and three years of missing measurement, for a few hours of work. None of it touches design.

Phase 1~1–2 days

Fix the information architecture

  • Convert the three service posts from _posts to real pages — kill the 27 duplicates and the nonsense /services/2014/09/21/ URLs
  • Add jekyll-sitemap; delete the hand-written sitemap.xml
  • Add canonical, hreflang, and Open Graph tags with a proper share image
  • De-duplicate the nav/sidebar ids into one shared include
  • Add netlify.toml so the build command lives in the repo, not only in the dashboard

Do this before any redesign — it is where the search visibility actually is, and it makes the templates safe to restructure.

Phase 2~2–3 days

Establish the style system

  • Write the token layer: colour ramp, fluid type scale, 4px spacing, two breakpoints
  • Convert Proxima Nova to subset woff2 and wire up @font-face; drop the .otf files and Quattrocento Sans
  • Replace the Bootstrap grid with CSS Grid and drop Bootstrap, Popper and jQuery Easing
  • Retire the 30 !important declarations as the specificity conflicts they patch disappear
  • Strip Instafeed and the dead Instagram token from ttu.js

This is the unification ask. It is also what makes the redesign cheap to apply — and cheap to change later.

Phase 3~3–4 days

Apply the redesign

  • Rebuild the lander from the agreed mockup direction
  • Bring /spordiklass/ and /sporditeraapia/ onto the same system — they are the two pages currently held together by dead grid classes
  • Re-encode images to WebP with srcset and intrinsic dimensions; re-encode the hero video and give it a real poster frame
  • Rebuild the enquiry form: native validation, a honeypot, and an error state that is actually reachable

Deliberately last. Everything above stands on its own even if the visual direction changes.

What I would not do

Not a rebuild, not a CMS migration, not a component framework, and not a blog. The site has no new requirements — the brief was explicit about that — and every one of those would add maintenance surface to a site that currently gets a handful of commits a year. The devop and Devop branches from 2017–18 can also go.
